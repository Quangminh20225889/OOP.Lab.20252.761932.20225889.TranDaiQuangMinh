Question 1.3: Compare Swing and AWT elements.

Answer:
AWT and Swing are both Java GUI toolkits and their programming style is similar:
both use containers, components, layout managers, and event listeners.

The main differences are:
- Top-level containers:
  AWT uses Frame, Dialog, and Applet.
  Swing uses JFrame, JDialog, and JApplet.
- Component names:
  AWT uses components such as Label, Button, TextField, and Panel.
  Swing uses JLabel, JButton, JTextField, and JPanel.
- Component implementation:
  AWT components are heavyweight components, meaning they depend more directly on
  native operating system GUI components.
  Swing components are lightweight components written mostly in Java.
- Adding components:
  In AWT, components are added directly to the Frame.
  In Swing, components should be added to the JFrame content pane.
- Look and feel:
  AWT depends more on the platform look and feel.
  Swing supports a more flexible and pluggable look and feel.


Question 14: What happens when you do not update Aims to catch exceptions
generated when the play() methods are called?

Answer:
After play() is changed to throw PlayerException, PlayerException is a checked
exception. Therefore, any method that calls play() must either catch it with a
try-catch block or declare it with throws PlayerException.

If Aims is not updated, the program will not compile. The compiler will report
an unhandled exception error at the places where play() is called. In our Aims
program, this is handled by catching PlayerException, printing information such
as getMessage(), toString(), and printStackTrace(), and continuing the program
without crashing.
